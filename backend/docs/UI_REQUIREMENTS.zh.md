# CVAgent 工作台界面需求与验收

## 目标

CVAgent 是独立的简历 Agent 产品。界面复用旧插件已经验证过的工作台信息架构，但运行时、状态和数据全部来自 CVAgent，不依赖 DSH。

## 视觉决策

- 采用 DSH 原型的白色、浅灰、蓝色视觉体系；不采用深色外壳。
- 顶部是轻量应用栏；左侧是工作区导航；中间是 Agent 对话和任务执行过程；右侧是当前简历、模板、草稿和验收上下文。
- 主标题使用“Agent 助手”，避免泛化的“简历工作台”标题。
- 信息密度参考 Codex/原型工作台：任务、工具步骤和结果在同一会话中连续出现。
- 源简历、草稿、渲染结果和正式版本要在界面上明确区分。

## 交互要求

1. 用户能在左侧设置工作区、简历文件和目标页数。
2. 用户能在中间发送任务，看到 Agent 回复和工具执行状态。
3. Agent 生成草稿后，右侧显示“草稿未保存”，不能误显示为正式版本。
4. 生成渲染结果后，右侧提供当前预览入口。
5. 只有真实浏览器测量通过验收，且用户明确确认，才允许保存正式版本。
6. 同一会话复用同一个 `sessionId`；会话不能中途切换工作区或简历文件。
7. 没有工作区或服务错误时，错误出现在当前界面，不弹出第二套浏览器/窗口选择器。

## 数据来源约束

- 工作区身份来自 `.cvagent/workspace.json`。
- 当前简历来自用户指定的 Markdown 文件。
- 草稿来自 `.cvagent/drafts/<taskId>/`。
- 渲染预览来自当前会话生成的 `.cvagent/renders/<taskId>/`。
- 正式版本来自 `.cvagent/versions/<versionId>/`。
- 界面不自行维护第二份简历内容或任务状态。

## 验收标准

- 白色 DSH 风格页面可打开，三栏结构稳定，无深色主背景。
- 导航、任务、对话、上下文四层信息关系清楚。
- `npm test` 全部通过。
- 首页、健康检查和静态资源可从真实服务进程加载。
- 界面文案不出现 DSH、MCP、旧插件运行时依赖。
- 旧插件目录没有新增或修改 CVAgent 运行时代码。
