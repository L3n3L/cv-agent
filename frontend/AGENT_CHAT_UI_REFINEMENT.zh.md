# CVAgent Agent 对话 UI 去 AI 味优化对接文档

> 状态：历史方案，已被 `AGENT_CHAT_CODEX_ALIGNMENT_RESEARCH.zh.md` 第 8 节复核修正
> 范围：`cvagent-ui-demo-v2` 的 Agent 助手抽屉  
> 原则：只优化信息层级、密度和视觉表达，不改变 Agent 协议、会话数据、简历渲染和按钮行为。

> 重要覆盖说明：本文前面的“用户消息不使用气泡”等规则属于上一轮过度简化方案，不再作为实现依据。当前以 Codex 对齐调研文档为准：用户消息保留右侧浅灰轻气泡，Agent 输出采用正文流，工具过程使用可折叠 Item，普通建议不生成“采纳建议 / 打开预览”按钮。

## 1. 结论先行

当前 Agent 对话布局基本可用，但视觉上仍然像“AI 对话模板”：标题、上下文卡片、时间、头像、气泡、执行状态卡片、操作按钮和输入框全部被独立强调，导致信息没有主次。

这轮不需要重做四块工作台布局，应该只重构 Agent 抽屉内部的表达方式：

1. Agent 抽屉是工作台的辅助控制台，不是一个独立页面。
2. 当前会话和简历信息已经在工作台顶部出现，抽屉内不再重复做成卡片。
3. Agent 回复采用“正文优先、轻边界”的表达；用户消息只保留轻微底色区分。
4. 执行过程采用一组紧凑的状态行，不再使用大块任务卡。
5. 输入区固定在底部，消息流单独滚动，首屏必须能看到输入框。
6. 蓝色只表示可执行操作，红色只表示阻断项，其余信息全部退到灰阶。

## 2. 调研依据

OpenAI 对 Codex 的产品说明把 Codex 定义为 Agent 的工作指挥台：任务按项目和线程组织，用户在任务线程中查看结果、审阅变更并继续协作，而不是把所有内容包装成一组互相竞争的卡片。[Introducing the Codex app](https://openai.com/index/introducing-the-codex-app/)

OpenAI 的使用说明把核心界面概括为侧栏、项目、设置和聊天窗口；这说明聊天窗口承担的是持续工作上下文，而不是重复解释产品状态。[Working with Codex](https://openai.com/pt-BR/academy/working-with-codex/)

OpenAI 对 harness engineering 的描述强调：应用 UI、日志和指标应对 Agent 与用户“可读”。对应到 CVAgent，就是把“正在做什么、结果是什么、下一步能做什么”直接表达出来，减少装饰性容器和重复说明。[Harness engineering](https://openai.com/index/harness-engineering/)

以上是对产品原则的归纳，不是对 Codex 内部源码的复制；具体视觉决策以当前 CVAgent 的简历制作场景为准。

## 3. 当前问题定位

当前实现位于 `index.html`、`app.js` 和 `styles.css`：

| 区域 | 当前问题 | 处理结论 |
| --- | --- | --- |
| 抽屉头部 | “按需辅助”“Agent 助手”“收起”三层信息，标题偏重 | 保留 `Agent` 与收起操作；删除“按需辅助” |
| 上下文 | `assistant-context` 再次展示当前草稿，和工作台顶部重复 | 删除卡片边框，改成一行弱提示，或直接删除 |
| 消息头 | 每条消息都展示头像、姓名、时间，视觉噪声大 | 保留身份，但缩小头像和时间；相邻同角色消息合并视觉连续性 |
| Agent 气泡 | 灰色大气泡像通用 AI 模板 | Agent 消息改为无卡片正文；只保留很浅的段落分隔 |
| 用户气泡 | 浅蓝块面积偏大，和主操作蓝色竞争 | 保留浅蓝底，但降低面积、圆角和填充 |
| 执行状态 | 三行状态被包进大块 run-card，且每行重复时间 | 改为紧凑状态组：小圆点 + 状态 + 一次时间 |
| 操作按钮 | “采纳建议”“打开预览”像另一个按钮组 | 只在最新 Agent 回复下展示，使用低强调文本按钮 |
| 输入区 | 占用较高，底部提示“当前会话草稿”与顶部状态重复 | 固定底部；删除重复说明；保留 placeholder、发送和必要快捷键 |
| 纵向空间 | 内边距、消息间距、气泡内边距同时偏大 | 通过统一节奏压缩，不用缩小正文可读字号 |

## 4. 设计规格

### 4.1 Purpose Statement

让用户在编辑简历时可以随时向 Agent 提出修改要求，并能快速理解 Agent 的建议、执行进度、阻断原因和下一步动作。Agent 面板必须服务于“改内容—重新渲染—查看结果”，而不是让用户阅读一套额外的产品说明。

### 4.2 Aesthetic Direction

`Luxury / refined`：克制、低对比、少容器、强排版秩序。高级感来自留白节奏、文字层级和颜色克制，而不是阴影、渐变、圆角卡片或大量图标。

### 4.3 Color Palette

沿用 v2 已有视觉令牌，不新增颜色：

- 主文字：`#17202A`
- 正文：`#667281`
- 辅助文字：`#98A2AE`
- 分割线：`#DDE2E8`
- 工作操作蓝：`#2F6FED`
- 用户消息浅蓝：`#EEF4FF`
- 阻断红：`#C74634`
- 页面背景：`#F6F7F9`

禁止：紫色、蓝紫渐变、彩色状态点、装饰性渐变背景。

### 4.4 Typography

- 正文和控件：`IBM Plex Sans`, `Microsoft YaHei`, sans-serif
- 时间、状态和技术字段：`IBM Plex Mono`, monospace
- 标题不超过 18px；正文 12px；辅助信息 10px；时间 9px
- 不使用 Inter、Roboto、Arial、system-ui 等通用字体

### 4.5 Layout Strategy

抽屉采用“标题—消息流—输入区”的纵向工作台结构，不再使用多层嵌套卡片：

```text
Agent                         收起
校招一页版 · 当前草稿
────────────────────────────
              今天 · 10:24
CVAgent  已载入当前简历和校招标准。
你       把实习经历改成……
         ├ 已读取简历与模板       10:25
         ├ 内容检查完成           10:25
         └ 排版验收未通过         2 页 / 目标 1 页
CVAgent  当前有 3 个排版阻断项。
         采纳建议    打开预览

描述你要怎么改……             发送
```

其中：

- 抽屉头部高度约 54px，标题只出现一次。
- 上下文最多一行，不使用独立背景卡片。
- `.chat-stream` 是唯一纵向滚动区域。
- `.composer` 固定在抽屉底部，不参与消息流滚动。
- 执行状态组与触发它的 Agent 回复相邻，不能漂浮到另一段空间。

## 5. 具体落地规则

### 5.1 头部和上下文

- “按需辅助”删除。
- “Agent 助手”改为“Agent”。工作台左上角已经是 CVAgent，不需要再次解释产品类型。
- `收起`保留，使用普通文本操作，不做实心按钮。
- `assistant-context` 删除边框、背景和大内边距；如果保留，只显示：`校招一页版 · 当前草稿`。
- `Agent 修改只作用于当前会话`改为 hover/title 或低对比辅助文本，不占一整行。

### 5.2 消息

- Agent 消息：正文直接放在消息流中，背景透明；必要时只使用 `#F8F9FA` 的极浅段落底色。
- 用户消息：保留浅蓝底，但最大宽度不超过消息区的 88%，右侧对齐或保持当前左侧结构但减少气泡面积。
- 头像从 30px 缩到 26px；仅用于识别角色，不承担装饰作用。
- 同一角色相邻消息不重复放大姓名；第一条显示姓名，后续只显示正文。
- 时间不在每条消息中重复出现；会话分隔和最新消息可保留一次时间。
- 消息正文行高约 1.55，段落间距 8px；不要通过增大气泡 padding 制造留白。

### 5.3 执行过程

- `run-card` 去掉大面积背景和厚重左边框，保留一条极浅的引导线即可。
- 每个状态行高度 24px 左右。
- 已完成状态使用灰蓝色小圆点或细勾；不要使用大圆形徽章。
- 阻断状态使用红色文字；“3 个阻断项”只出现一次。
- 时间放在状态组右侧统一显示，避免每行重复。
- 状态组标题可写为 `检查结果`，不要再次写“已读取简历与模板”等解释性长句。

### 5.4 操作按钮

- 操作只挂在最新 Agent 回复下，其他消息不显示操作。
- `采纳建议`为主操作，`打开预览`为次操作；均采用低高度、低圆角文本按钮。
- 不要再把操作按钮包进卡片或独立 footer。
- “打开预览”仍然调用现有 `data-open-preview`，不改变行为。
- “采纳建议”仍然调用现有 `data-suggest`，不改变行为。

### 5.5 输入区

- `.composer`固定在底部，边框保持 1px，阴影极弱或取消。
- 默认高度控制在 76–92px；textarea 只在内容增加时扩展。
- 删除“当前会话草稿 · 修改后需要重新渲染”等重复提示。
- placeholder 保留具体示例，但控制在一行或两行内。
- 发送按钮保留蓝色实心状态，尺寸不超过 76×34px。
- `Enter 发送`作为紧凑辅助文本放在按钮旁，不单独形成 footer 区块。

## 7. 需要删除或收敛的冗余

- 删除 Agent 抽屉内的“按需辅助”。
- 删除独立的 `assistant-context` 卡片样式；保留一行上下文即可。
- 删除每条消息重复的时间戳，或改成只在消息组首尾显示。
- 删除 Agent 消息的大块灰色气泡。
- 删除执行状态行的重复时间和大圆形状态徽章。
- 删除输入框底部重复解释，不删除发送行为和必要快捷键。
- 不新增图标、渐变、装饰性插画、评分徽章或“AI 正在思考”类空转文案。

## 8. 工程实施顺序

### P0：结构收敛

1. 只改 Agent 抽屉模板和对应 CSS。
2. 保留现有 `renderChat()`、`bindChat()` 的事件选择器。
3. 确认 `.chat-stream` 单独滚动，`.composer`始终可见。
4. 确认打开/收起 Agent、采纳建议、打开预览、发送消息行为不变。

### P1：视觉精修

1. 压缩消息间距和气泡 padding。
2. 调整状态组为轻量时间线。
3. 统一按钮高度、圆角和文字颜色。
4. 在 1280×800、1440×900、窄屏三个视口验收。

### P2：可选增强

1. 相邻同角色消息自动合并消息头。
2. 输入框按内容自动增高，但设置最大高度。
3. 状态组支持展开/收起详细信息。

P2 不应阻塞本轮视觉验收。

## 9. 验收清单

- [ ] Agent 抽屉打开后，首屏同时看到标题、至少两段对话、执行结果和输入框。
- [ ] 页面不需要先滚到底部才能聊天。
- [ ] 抽屉内没有重复的“当前草稿”大卡片或页面级说明。
- [ ] Agent 正文、用户消息、执行状态、操作按钮四种层级一眼可区分。
- [ ] 对话内容区域滚动时，输入区不跟着滚走。
- [ ] 蓝色只出现在操作按钮和用户消息弱底色；红色只出现在阻断项。
- [ ] 1280×800 下不出现横向滚动，不因 Agent 面板变宽导致 MD/A4 不可用。
- [ ] 关闭 Agent 后，工作台 MD/A4 布局和已保存分栏宽度不受影响。
- [ ] 现有真实模板 iframe、渲染状态、会话切换和建议按钮行为不回归。

## 10. 本轮明确不做

- 不把 Agent 对话改成全屏聊天页。
- 不增加独立的“AI 设置”“能力说明”“模型信息”区域。
- 不把每个 Agent 动作都做成一张卡片。
- 不用截图作为像素级实现依据；截图只用于确认层级和密度方向。
- 不改变简历内容、模板库、真实模板渲染和 MCP / 原生工具接入。
