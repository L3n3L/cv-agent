# CVAgent UI 重构对接复盘与工程执行基线

日期：2026-09-17  
状态：待工程执行  
适用项目：`CVAgent`  
对齐目标：在不破坏简历制作业务闭环和 DSH 原生渲染基准的前提下，将 CVAgent 工作台提升到可持续迭代、可视觉验收的产品级 UI。

## 1. 结论先行

不建议全量推倒重写，也不建议继续在现有页面上零散调颜色和间距。

推荐采用：

> 保留简历领域内核，重构前端工作台壳层；先修复布局和主流程，再补齐模板、排版诊断和 Agent 反馈体验。

预计第一阶段重构范围约为前端层的 30%～40%，不改变核心 API、渲染器、状态机和文件存储语义。

### 保留的权威能力

- `src/migrated/resume-engine/`：模板、Markdown/A4 渲染、图标和视觉结果基准；
- `src/core/workflow.js`：简历制作状态机和失效规则；
- `src/core/session.js`、SessionStore：会话、恢复和持久化；
- `src/agent/resume-tools.js`：Agent 工具边界；
- `resume_prepare → resume_read → resume_check → resume_write → resume_render → resume_metrics → resume_finalize → 用户确认 → 保存正式版本` 工序；
- DSH 原生模板和渲染结果作为两边简历成品一致性的 Golden Reference。

### 第一阶段重构的主要文件

- `public/index.html`
- `public/app.js`
- `public/styles.css`
- `public/workbench.css`
- `test/ui-contract.test.js`（同步更新 UI 契约测试）

第一阶段暂不迁移 React/其他前端框架。先把现有 UI 壳层、状态映射和响应式布局理顺；只有在此后原生 JS 仍然明显阻碍组件化迭代时，再单独评估 UI 层迁移。

## 2. 当前 UI 验收结论

当前页面是“功能可用的工程演示版”，还不是“可交付的产品工作台”。核心问题不是视觉风格不够漂亮，而是用户完成简历任务时缺少稳定、明确、可恢复的操作路径。

### 已确认的问题

1. **布局存在硬性裁切**

   当前页面有 `min-width: 1050px/1120px/1180px` 等多层约束，窄窗口下出现横向裁切。实测浏览器视口约 711px，而页面内容宽度约 1050px，不能视为响应式支持。

2. **主工作区被导航和工具栏挤压**

   左侧导航、来源设置、顶部工具栏叠加后，真正用于编辑和查看 A4 的区域变小，用户需要频繁滚动或理解隐藏状态。

3. **模板选择缺少真实结果预览**

   模板卡片和模板工坊目前使用抽象线条缩略图。用户无法在选择模板前判断真实字体、密度、图标、页数和内容层级。

4. **排版验收不可行动**

   当前检查区能够表达“需要调整”，但没有把问题定位到页面、模块和推荐动作。例如应明确显示“当前 2 页、目标 1 页、第 2 页内容不足，建议先降低 Section Gap 或调整项目描述长度”。

5. **手动微调反馈不完整**

   字号、行高、Section Gap、页边距等控件已经存在，但缺少应用前后的差异、重置/撤销、当前变更是否已重新渲染，以及图标信息等待状态的可靠反馈。

6. **Agent 页面缺少过程可见性**

   当前 Agent 主要表现为一次性对话。用户看不到读取材料、内容检查、写入草稿、渲染、测量和最终验收之间的关系，也无法快速判断卡在哪一步。

7. **导航层级与业务主线不匹配**

   工作区、模板、检查、版本、Agent 等入口权重接近，但用户的主任务其实是“制作并确认一份可投递简历”。

8. **状态和版本容易被误读**

   草稿、当前渲染、正式版本和未通过验收的结果需要更强的视觉区分。任何未通过 `resume_finalize` 的结果都不能显示成“已完成”。

### 已确认的正向基础

- 白色、浅灰、蓝色工作台方向适合简历生产工具；
- 现有卡片、边框、按钮和状态颜色已经形成可复用基础；
- 业务保存门、草稿隔离和源文件保护方向正确；
- CVAgent 核心测试当前通过，UI 改造应避免破坏这些业务约束；
- 浏览器检查未发现明显 Console error，但“无报错”不等于“视觉验收通过”。

## 3. 产品 UI 目标

### 目标用户

正在制作、针对岗位修改并导出简历的求职者；同时包括需要快速审阅简历状态的产品/运营人员。

### 目标体验

用户打开后应该立即知道：

- 当前编辑的是哪一份简历；
- 当前处于草稿、渲染、验收还是正式版本阶段；
- 当前有几个阻断问题；
- 下一步应该点击什么；
- 修改后是否已经重新渲染和测量；
- 为什么现在可以或不可以保存正式版本。

### 推荐视觉方向

工业化、安静、面向重复工作的简历生产工作台。

- 保留浅色背景和低饱和蓝色强调色；
- 减少装饰性大卡片和空洞的宣传区域；
- 信息密度高但层级清楚；
- 使用状态标签、分段控件、工具提示和明确的下一步动作；
- A4 预览必须成为第一视觉对象，而不是被导航和说明文案抢走注意力；
- 统一使用现有产品字体和图标体系，不在本阶段随意更换字体或引入一套新设计语言。

## 4. 推荐的信息架构

将当前多入口收敛为四个产品级视图：

```text
工作区
├─ 简历制作（默认入口）
│  ├─ 内容编辑
│  ├─ A4 预览
│  ├─ 模板选择
│  ├─ 手动微调
│  └─ Agent 调整
├─ 排版验收
├─ 正式版本
└─ 设置 / 工作区信息
```

### 默认入口：简历制作

桌面宽屏建议使用三栏：

```text
左：工作区与当前任务
中：Markdown 编辑器 + A4 预览
右：当前状态、模板、排版问题、保存/导出
```

当窗口宽度不足时：

- 左栏变为可展开抽屉；
- 右栏变为可展开检查面板；
- 中间编辑/预览区域保持可用；
- 页面不得通过 `body min-width` 强行撑开；
- 不允许用 `overflow: hidden` 掩盖内容裁切。

### 主操作层级

每个状态下只突出一个推荐动作：

| 当前状态 | 主动作 | 次动作 |
| --- | --- | --- |
| 未加载工作区 | 设置工作区 | 查看说明 |
| 已加载源简历 | 开始检查 | 编辑内容 |
| 检查未通过 | 查看阻断项 | 返回编辑 |
| 已生成草稿 | 预览草稿 | 继续调整 |
| 已渲染未测量 | 开始测量 | 返回编辑 |
| 测量未通过 | 查看排版问题 | 手动微调 / Agent 调整 |
| 验收通过未确认 | 确认并保存版本 | 继续预览 |
| 已保存正式版本 | 导出 PDF/HTML | 创建新版本 |

## 5. UI 状态契约

UI 不能自行推断业务状态，应消费工具和 API 返回的结构化字段：

```text
state
blockers[]
nextTool
nextAction
completionAllowed
sessionId
taskId
sourceHash
contentRevision
templateRevision
presentationRevision
renderId
metrics
```

### 必须可视化的状态

- 当前 Session 和工作区；
- 当前源文件或草稿身份；
- 当前内容、模板、presentation、render、metrics 是否匹配；
- 当前页数与目标页数；
- 溢出、稀疏页、页面平衡、图标和字体等阻断项；
- 最后一次成功动作和下一步动作；
- 保存正式版本的阻断原因。

### 完成门

以下条件任一不满足，UI 不得显示“完成”，也不得允许保存正式版本：

- 当前内容已经通过 `resume_check`；
- 当前内容和模板已经重新渲染；
- 测量结果绑定当前 `renderId`；
- `resume_finalize` 返回 `accepted=true` 且 `completionAllowed=true`；
- 用户明确确认保存。

内容、模板或 presentation 发生变化后，旧的 check、render、metrics、finalize 都必须在 UI 上显示为失效或待重新执行。

## 6. 分阶段执行计划

### P0：布局和壳层稳定性

目标：在不改变业务行为的情况下，让工作台可稳定使用。

- 清理 `styles.css` 与 `workbench.css` 的重复布局规则；
- 建立统一的根布局和 CSS token；
- 移除依赖 `body min-width` 的布局策略；
- 建立至少 3 个断点：窄桌面、中等桌面、宽桌面；
- 处理三栏与抽屉之间的切换；
- 固定编辑器、预览区、检查区的最小可用尺寸；
- 顶部工具栏在窄宽度下换行或进入更多操作菜单；
- 保持已有 DOM ID、按钮行为和 API 调用兼容，减少业务回归风险。

### P1：核心制作体验

- 收敛导航和主流程；
- 将模板缩略图替换为真实内容的 A4 缩略渲染；
- 在预览区域显示页数、目标页数和关键排版指标；
- 将排版检查改为“问题 → 影响 → 推荐动作”；
- 手动微调支持应用中、已应用、待重新渲染、渲染失败、已测量等状态；
- 增加重置和撤销能力；
- 草稿、当前预览和正式版本使用不同状态标签；
- 保存/导出按钮显示明确的 disabled reason。

### P2：Agent 任务体验

- 将一次性消息改成任务时间线；
- 显示工具步骤和结构化结果；
- 显示当前阻断原因与下一步；
- 支持中断、重试、继续 Session；
- 真实模型执行完成后再增加流式事件，不要为了“像聊天”而先重写业务状态。

### P3：工程化整理

- 将页面状态、渲染状态和视图组件拆分；
- 为关键 UI 状态增加数据驱动渲染函数；
- 增加浏览器级视觉回归；
- 评估是否有必要迁移到 React/其他框架；
- 如果迁移，必须保持 API、Session、工具工序和成品 HTML/PDF 不变。

至少检查以下尺寸：

```text

1280 × 800
1440 × 900
```

每个尺寸必须满足：

- `document.documentElement.scrollWidth <= document.documentElement.clientWidth`，或水平滚动仅存在于明确的内部区域；
- 主要按钮和文字不被裁切；
- 编辑器、A4 预览和检查面板均可访问；
- 模板卡片不溢出；
- 弹层不遮挡关键操作，且可以关闭；
- 窄宽度下三栏有明确的折叠/展开方式。

- [ ] 首屏直接进入可工作的简历制作场景，不展示大段产品说明；
- [ ] A4 预览是主视觉对象；
- [ ] 当前状态、阻断原因和下一步动作一眼可见；
- [ ] 模板缩略图与最终渲染的内容、字体和密度具有可比性；
- [ ] 草稿、预览和正式版本不会混淆；
- [ ] 不存在横向裁切、文字重叠、按钮跳动、空白占位图和“等待但没有原因”的状态；
- [ ] 浏览器 Console 无新增 error/warn；
- [ ] 现有 `npm test` 全部通过。

## 11. 截图、参考图与 Codex 调 UI 的正确工序

### 11.1 截图的定位

截图是问题证据和回归证据，不是完整的 UI 设计规格。

截图可以回答：

- 当前哪里发生了裁切、拥挤或信息层级混乱；
- 修改后 A4 预览是否变大或变小；
- 手动调整、导出、保存等控件是否仍然存在；
- 当前状态、阻断原因和下一步动作是否可见。

截图不能单独回答：

- 哪些按钮是业务必需的；
- 面板打开后应该覆盖、挤压还是折叠；
- 哪些状态变化必须触发重新渲染；
- 哪些 API、Session 和保存门不能被改变。

因此，不能把一张 AI 生成的“漂亮目标图”直接交给工程者作为实现依据。生成图可能遗漏手动微调控件、改变信息架构，或为了容纳新面板而缩小 A4 预览区域。

### 11.2 目标参考的正确形式

每个关键页面应按“状态”制作参考，而不是为每个页面做一张自由发挥的概念图。

至少准备以下状态：

1. 默认工作台：Markdown 编辑器 + A4 预览；
2. 手动调整打开：字号、行高、Section Gap、页边距、图标缩放、重置和应用全部可见；
3. 排版检查打开：问题、影响、推荐动作和重新渲染入口可见；
4. Agent 执行中：读取、检查、写稿、渲染、测量、验收过程可见；
5. 验收通过：用户确认和保存正式版本入口可见。

每张参考图必须同时附带以下文字契约：

```text
当前状态：
viewport：
本轮要解决的问题：
必须保留的控件：
A4 预览最小可用尺寸：
允许折叠或覆盖的区域：
不能改变的业务行为：
验收条件：
```

### 11.3 CVAgent 的关键 UI 不变量

后续任何目标图、原型或 CSS 改动都必须满足：

- A4 预览是工作台的核心视觉区域，不能因固定增加右侧栏而无提示地变小；
- `手动调整`入口必须持续可见；
- 手动调整必须包含字号、行高、Section Gap、页边距、图标缩放、重置和应用；
- 控制面板默认可以收起，打开时优先使用抽屉或浮层，不永久侵占预览宽度；
- 窄屏可以收起编辑器或检查面板，但不能隐藏 A4 预览和手动调整入口；
- 排版检查必须给出“问题 → 影响 → 推荐动作”，不能只显示“需要调整”；
- 草稿、渲染、测量和正式版本必须保持视觉区分；
- UI 不得自行推断 `completionAllowed`；
- 页面不得通过 `overflow: hidden` 掩盖水平溢出或控件丢失。

### 11.4 Codex 的推荐调 UI 循环

不要创建“全量美化 CVAgent”的开放任务。应采用以下循环：

```text
业务不变量
→ 状态级 UI 契约
→ 现状截图和 DOM 基线
→ 单问题实现
→ 浏览器截图复验
→ DOM 尺寸与交互检查
→ 测试回归
→ 下一问题
```

推荐拆分：

```text
任务 1：只修复页面级横向裁切
任务 2：只优化编辑器与 A4 预览比例
任务 3：只重做手动调整面板
任务 4：只重做排版检查状态
任务 5：只重做 Agent 执行过程
```

每个任务都必须提供：

- 真实启动命令和 URL；
- 指定 viewport；
- 修改文件范围；
- 必须保留的控件和业务行为；
- 明确验收标准；
- 修改后的测试和浏览器验证方式。

### 11.5 三层验收，不以截图单独作为完成条件

#### 视觉层

- A4 是否更大、更清楚；
- 所有业务按钮是否仍然存在；
- 是否发生文字裁切、重叠、遮挡或按钮跳动；
- 手动调整打开后是否仍能看到预览和应用结果。

#### 布局层

- 检查 `scrollWidth` 与 viewport 宽度；
- 检查编辑器、预览区和控制面板的实际尺寸；
- 检查窄屏下抽屉/浮层是否覆盖合理；
- 检查所有固定格式区域是否具备稳定尺寸约束。

#### 交互和业务层

- 手动调整能否打开、修改、重置和应用；
- 应用后是否重新渲染；
- 重新渲染后旧验收结果是否失效；
- 未通过验收时保存是否继续禁用；
- 是否保持 Session、renderId、metrics、finalize 和版本保存语义；
- `npm test` 是否全部通过。

### 11.6 参考图使用规则

- 真实页面截图：作为现状和回归基线；
- 标注截图或线框：作为布局和控件约束；
- AI 生成图：只作为风格探索，不作为业务和布局真值；
- 可点击 HTML 原型：优先于静态概念图，作为工程实现参考；
- 最终真值：状态契约、DOM 行为、真实浏览器截图和测试结果的组合。

如参考图与现有业务控件、A4 可用空间或保存门冲突，以业务契约和可运行页面为准。

### 11.7 顶部会话栏、预览收纳与模板库决策

#### 顶部区域的产品定义

顶部的 `CURRENT SESSION / 当前会话` 区域定义为“会话上下文栏”，不是当前页面标题。

它的职责是持续回答：

- 用户当前正在操作哪一份简历；
- 这份简历处于草稿、渲染、验收还是正式版本阶段；
- 当前简历绑定了哪个工作区和源文件。

因此，在同一 Session 内切换“工作台、预览、模板库、排版检查、投递版本”时，顶部会话栏保持稳定；内容区另行显示当前模块标题和说明。例如：

```text
顶部：校招一页版 · 草稿 · 需要重新验收
内容区：模板库 · 选择适合当前岗位的简历版式
```

以下行为必须同步更新顶部会话栏：

- 切换 Session：更新会话名称、状态和元信息；
- 切换工作区：更新工作区名称、源文件和可用版本；
- 内容、模板或排版参数变化：更新草稿/渲染失效状态；
- 进入正式版本：更新正式版本标识，但不能抹掉当前 Session 身份。

如果切换 Session 后顶部仍显示旧简历，属于状态绑定缺陷，不属于固定上下文策略。

#### 右侧预览必须可收纳

右侧 A4 预览和排版检查面板不能永久占用工作区宽度。桌面宽屏也必须提供明确的收纳入口：

- 面板展开时：显示 A4 预览、页数、排版状态、阻断原因和手动调整；
- 面板收起时：中间编辑/对话区扩展，右侧保留窄边栏按钮或顶部“显示预览”按钮；
- 面板再次打开时：恢复上次的滚动位置、预览页码和面板子状态；
- `显示预览` 与 `收起预览` 必须表达当前状态，不能两个状态都显示同一文案；
- 收起面板不能销毁当前预览状态，也不能让手动调整入口永久消失；
- 窄屏优先使用抽屉，宽屏优先使用可折叠侧栏，二者都必须可关闭。

收纳是空间管理，不是隐藏业务能力。收起后用户仍应能通过一个稳定入口回到预览和手动调整。

#### 模板库必须使用真实缩略图

模板库不能只展示模板名称、修订号和抽象线框。每个模板卡片至少包含：

- 真实 A4 比例缩略图；
- 模板名称和版本号；
- 当前简历套用后的代表性内容密度；
- 页数、字体/图标风格等关键差异；
- 当前使用、预览、选择等明确动作。

缩略图应来自同一套模板和渲染规则，不能由前端另画一套与最终成品无关的示意图。缩略图与最终 A4 成品在以下方面必须可比：

- 字体层级和字号关系；
- Section 间距和页面密度；
- 图标、分隔线和颜色；
- 页数、内容溢出和空白分布。

模板卡片的缩略图是选择依据，不是装饰图。用户选择前应能大致判断模板是否适合当前简历和目标岗位。

#### 对应验收用例

- [ ] 在同一 Session 中切换模板库，顶部仍显示当前简历身份，内容区显示“模板库”；
- [ ] 切换到另一 Session，顶部会话名称、状态和元信息同步变化；
- [ ] 点击“收起预览”后，中间工作区变宽，右侧保留可恢复入口；
- [ ] 点击“显示预览”后，A4、排版状态和手动调整恢复可见；
- [ ] 模板库每张卡片都有真实内容缩略图，而不是空白或抽象占位图；
- [ ] 选择模板后，缩略图、A4 预览和模板状态绑定同一模板版本；
- [ ] 收纳/展开预览不改变 Session、草稿、renderId、metrics 和 finalize 语义。
