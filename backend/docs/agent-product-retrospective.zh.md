# 独立简历 Agent 对接复盘

日期：2026-09-11  
状态：MCP 核心工序对齐与单用户可恢复 Session 第一轮已落地

## 1. 目标修正

本产品不依赖 DSH、Cordis 或 MCP。原有插件只作为可复用的纯简历能力和历史问题样本来源；独立产品拥有自己的 Agent、工作区、模板、渲染和版本运行时。

## 2. 最终工序

开发顺序采用“最小闭环优先，日志同步贯穿”：

```text
确定独立边界
→ 定义后端状态与工具契约
→ 打通聊天到草稿写入的最小前后端链路
→ 接入结构化运行日志
→ 接入模板、渲染、测量和验收
→ 接入草稿/正式版本和用户确认
→ 完成浏览器验收与回放测试
```

不能先做完整 UI，也不能先做一套孤立日志系统。日志必须从第一条 Agent 任务开始记录，但它是横切能力，不是产品主交付物。

## 3. 架构决策

- Deep Agents：通用 Harness，负责规划、Skill、上下文和工具调用循环。
- 简历领域核心：负责工作区、内容、模板、渲染、指标和版本的唯一来源。
- 工具结果：使用结构化 `passed`、`blocked`、`nextTool`、`completionAllowed` 和版本标识。
- 完成门：没有当前版本的渲染和测量结果，Agent 不能宣称完成；未通过验收或未获得用户确认，不能保存正式版本。
- 日志：只做诊断，不成为业务状态来源；日志必须关联任务、简历、内容、模板和渲染身份。

第一版不额外维护一套与 Deep Agents 平行的显式 LangGraph 业务图。只有复杂长任务、并发子 Agent 或恢复需求超过现有能力时再扩展。

## 4. 已完成的第一、二阶段

- 建立干净的 `CVAgent/` 产品目录；
- 建立 Deep Agents JavaScript 接入边界；
- 建立任务上下文和状态转换；
- 实现草稿写入后清除旧渲染/指标；
- 实现稀疏页阻塞和用户确认后保存；
- 实现工具事件和脱敏 NDJSON 日志；
- 实现独立 `/health` 服务入口；
- 用自动化测试验证核心状态和日志关联；
- 建立 `.cvagent/workspace.json` 工作区身份；
- 建立安全相对路径读取和源文件保护；
- 建立素材列举与单文件读取工具，隐藏运行元数据和草稿；
- 建立 MCP 语义的 `resume_prepare`、`resume_read`、`resume_check`、`resume_write`、`resume_render`、`resume_metrics`、`resume_finalize` 核心工具；
- 建立 `POST /api/agent/run`，支持注入 Agent 做无模型回放测试；
- 建立按会话授权的渲染预览和浏览器测量回传；
- 修正缺少测量结果时“返回状态”和“任务快照”不一致的问题。
- 建立单用户本地 SessionStore，持久化 Session 快照、消息和事件，支持服务重启恢复；
- 前端增加历史 Session 列表和恢复入口；

## 5. 当前状态与未完成

- 已接入 Deep Agents 的真实模型调用入口；真实模型回放仍需要配置 `DEEPSEEK_API_KEY` 后单独执行；
- 素材目录读取、模板、渲染、浏览器测量回传和验收工具已经落地；服务端仍需要补充真正的浏览器自动测量；
- Markdown/A4 渲染器已经迁移为独立服务；运行时命名、资源接口和指标协议已统一为 CVAgent，不再依赖旧宿主命名；
- 独立 Agent 聊天 UI 已实现，但当前接口是一次性 `invoke`，尚未提供流式事件；
- 核心 HTTP/状态测试已完成，真实模型、流式事件和生产部署场景仍未完成端到端验收；
- UI 目前能恢复历史 Session，但还未完整展示工具事件和阻断原因。

后续所有代码、测试和日志都应落在 `CVAgent/`，不得重新向旧插件目录添加独立产品运行时依赖。
