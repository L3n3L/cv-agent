# DSH 简历 Agent 能力对齐：需求

## 目标

CVAgent 保持独立产品和独立工作区，不引入 DSH 运行时依赖；但在简历制作的内容决策、工具能力和可验证工序上，对齐 DSH `dsh-resume` MCP 的业务契约。

## 范围

本阶段补齐：

1. CVAgent 自有的完整简历生产契约：岗位定向、证据台账、压缩 STAR、内容保留优先级及一/两页验收策略；
2. 图标目录查询；
3. 基于真实 A4 测量结果的、受限且需用户确认才持久化的版式调优建议；
4. 明确的布局校验能力，并保持模板结构、展示参数和 Markdown 内容三者分离；
5. 将岗位/JD 投递版本作为正式版本元数据，而不是只保存一个无语义的快照名称。

不做：复用 DSH 的 `ctx.tools`、DSH 左侧栏、全局工作区绑定、MCP 常驻服务，或直接读写 DSH 的 `companies/` 目录。

## 用户故事与验收

1. 作为求职者，我希望 Agent 按真实证据和岗位相关性写简历，而不是只把句子润色得更长。
   - 当 Agent 处理简历时，它应先读取素材并报告证据缺口；不得虚构雇主、日期、指标或成果。
   - 当 Agent 重写要点时，它应把 STAR 压缩成可扫描的一至两行，而不是生成四段叙事。

2. 作为求职者，我希望一页或两页的要求不会导致 Agent 先删核心经历。
   - 当 A4 超页或稀疏时，系统应先建议展示参数和模板承载调整，再压缩重复、低相关技能和荣誉细节。
   - 当用户明确目标为两页时，系统应要求恰好两页且逐页密度均衡；一页规则不得覆盖明确的两页目标。

3. 作为求职者，我希望 Agent 只能使用真实存在的图标。
   - 当 Agent 需要图标时，`icon_list` 应返回可查询、有限数量的已注册图标；未知 token 仍由检查和渲染拒绝。

4. 作为求职者，我希望“自动调版”不会暗中改变模板或正文。
   - 当真实 A4 测量不通过时，`presentation_suggest` 只能根据当前测量产生最多三轮的受限建议，默认不写入。
   - 当用户明确确认应用建议时，系统才可调用 `presentation_update`；该变更必须产生新 renderId 并重新测量、验收。

5. 作为求职者，我希望模板结构调整是受校验的，不会把渲染器带坏。
   - 当 Agent 提交布局描述时，`layout_validate` 应返回规范化结果和错误；非法布局不得保存。
   - 当前阶段只校验和预览布局语义，不新增绕过模板修订的布局持久化入口。

6. 作为求职者，我希望每份投递版本能说明投给谁、基于哪个 JD、使用哪个模板修订。
   - 当用户保存已验收版本时，版本元数据应可选记录 `targetRole`、`company`、`jobDescriptionPath`；未提供时仍兼容当前正式版本流程。

## 非功能约束

- 工具名称保持 CVAgent 命名，不复制 `jobhunt_*`；
- 浏览器测量仍只能由产品回调调用，模型不可伪造 `resume_metrics`；
- 所有变更继续服从 `renderId`、`contentVersion`、`templateRevision` 的绑定验收；
- 新工具返回小而结构化的摘要，避免把全量图标或全量模板/CSS 注入模型上下文；
- 自动化测试覆盖工具边界；真实浏览器回归覆盖“建议 → 用户确认 → 新渲染 → 测量”的闭环。
