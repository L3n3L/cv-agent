# CVAgent 模板生命周期：需求与对接复盘

## 1. 结论与范围

CVAgent 已迁移 DSH 的基础模板目录、TemplateSpec 校验、模板复制和覆盖前历史快照；但没有迁移 DSH 的 `DesignBrief → template_generate → template_save → template_versions → template_restore` 产品闭环。

本规格将当前用户工作区定义为其长期简历资产库。用户通常不会频繁更换工作区，因此本期不建设跨工作区的“全局我的模板”或模板市场。

## 2. 用户故事

1. 作为求职者，我可以浏览不可修改的官方模板，并将一个模板用于当前简历。
2. 作为求职者，我可以对 Agent 说“生成一份极简产品经理模板”，先看到真实 A4 候选，再决定是否保存为我的模板。
3. 作为求职者，我可以基于现有模板做结构化改造而不破坏原模板。
4. 作为求职者，我可以持续迭代我的模板，查看、恢复任一修订，并让已保存简历仍能定位其当时使用的模板修订。
5. 作为求职者，我只想调整当前简历的字号、间距或颜色时，不希望误创建或修改一个可复用模板。

## 3. 业务规则

- 官方模板仅存在于应用包内，标记为 `immutable=true`，不得被覆盖或删除。
- 工作区 `templates/` 是用户的模板库；Agent 新建模板和用户手动派生模板均写入这里。
- 结构、模块顺序、页面规格、独立 CSS 的改动属于模板修订；字号、行距、边距、颜色和图标微调默认属于当前简历的 `presentation`。
- Agent 在用户仅要求“看看/给方案”时只能生成候选，不能落盘为模板或切换当前模板。
- 当用户明确要求“创建”“保存为模板”或“应用这个新模板”时，Agent 可继续执行校验、渲染、A4 测量并保存，无需重复确认。
- 自定义模板创建时必须是新的 ID；编辑已有模板必须显式声明替换影响，系统先生成不可变修订快照。
- 恢复历史模板不静默倒退：恢复结果成为当前模板的一个新修订。
- 每个正式简历版本必须记录 `templateId`、`templateRevision` 与可解析的模板快照身份；不能仅记录一个会随时间变化的模板名称。

## 4. 验收标准

1. 当用户请求生成新模板时，系统应先返回经 Schema 校验的候选 TemplateSpec、设计理由和 CSS 质量审计，且不写入工作区。
2. 当用户明确保存候选时，系统应写入工作区模板、生成 revision 1 快照，并返回模板 ID、修订号和来源信息。
3. 当用户基于官方模板改造结构时，系统应先创建独立自定义模板，官方模板内容保持不变。
4. 当用户更新自定义模板时，系统应先保留旧修订，再生成递增 revision；恢复任一旧修订后 revision 仍应递增。
5. 当内容、模板或 presentation 改变时，系统应使旧渲染和旧测量失效，并要求重新执行 A4 验收。
6. 当用户只做 presentation 微调时，系统不应创建模板文件或模板修订。
7. 当旧工作区含有平铺的 `templates/<id>.json` 与 `.css` 时，系统应可继续加载；首次新式更新时应建立可追溯修订快照。

## 5. 非目标

- 多用户、云同步、跨工作区模板市场。
- Agent 任意写 HTML/JavaScript 或绕过 TemplateSpec/CSS 校验。
- 在未真实渲染、测量、验收前声称新模板已适配目标页数。
