# CVAgent Agent 工作台视觉高级感调研

日期：2026-09-17

## 结论先行

需要单独调研，而且这不是“加阴影、加渐变、换几个图标”的问题。

当前 Demo 的信息架构已经接近正确：左侧工作区与会话，中间 Markdown 和真实 A4，右侧按需打开 Agent。现在不够高级的根因是视觉语言还没有收敛：边界、圆角、状态、辅助文案和标题层级都在争夺注意力，导致页面像一个 AI 功能样板，而不是一个稳定的生产工具。

用户给出的参考图传达的不是某个具体组件，而是一种“安静的高级感”：低饱和、弱对比、字体有明确层级、留白有节奏、没有多余装饰。它可以作为气质参考，但不能直接作为页面重构的像素目标。

## 视觉方向

### 采用：Luxury / refined（克制的专业编辑器）

CVAgent 不应追求炫技式的 AI 视觉，而应像一件专业的编辑工具：

- 视觉焦点只有当前简历成品和下一步动作；
- 颜色主要用于表达状态，不用于装饰；
- 通过字体、留白和比例建立层级，而不是通过卡片数量建立层级；
- 所有能力都可以被找到，但默认界面只展示当前任务需要的能力；
- 让用户感觉“系统很稳”，而不是“系统正在努力展示自己”。

## 调研得到的共同原则

### 1. 先用字体建立层级，再用颜色和装饰

[Geist Typography](https://examples.vercel.com/geist/typography) 将字号、行高、字距和字重作为成套的类型级别，而不是让每个组件自行决定字体。

OpenAI 插件中的 [Geist 设计规则](https://github.com/openai/plugins/blob/main/plugins/vercel/skills/geist/SKILL.md) 也明确强调：层级首先由排版承担，颜色和装饰只做辅助；标题应清楚，次要文字应克制可读，元数据可以使用等宽字体。

对 CVAgent 的意义：当前页面不应该继续增加颜色和标签，应该先统一标题、正文、元数据和状态的排版规则。

### 2. 中性色不是“没有设计”，而是为结果让位

[Geist Colors](https://examples.vercel.com/geist/colors) 将背景划分为有限的背景层级，并建议默认背景与次级背景谨慎区分。

CVAgent 应该使用一个近灰工作区背景、一张白色 A4 纸和一套很少的文字灰度。蓝色只表示可操作的主动作，红色只表示阻断，不能把每个模块都染成不同的状态色。

### 3. 留白需要 token，而不是凭感觉堆出来

[Radix Spacing](https://www.radix-ui.com/themes/docs/theme/spacing) 提供了连续的间距尺度；[USWDS Typography](https://designsystem.digital.gov/components/typography/) 则强调标题应更靠近其内容，内容组之间使用更大的间距。

这能解决当前 Demo 中“每一块都差不多远”的问题：同一组内容要紧，组与组之间要松，顶部工作区不能把垂直空间平均分配给所有信息。

### 4. 高级感来自状态完整，而不是状态更多

[Vercel Web Interface Guidelines](https://vercel.com/design/guidelines) 强调标题、帮助、加载、空状态、错误状态和成功状态都需要有明确设计；状态不能只依赖颜色表达，也不应该出现没有下一步的死路。

对 CVAgent 的意义：不要同时显示“草稿”“待验收”“待渲染”“2 页”“有问题”等多个孤立标签。应该输出一个可行动的结论，例如：

> 暂不能导出 · 当前 2 页 · 下一步：压缩项目经历

## 当前 Demo 的视觉问题诊断

### P0：界面表面太多

当前侧栏、工作区、编辑器、预览区、状态区和辅助区都带有自己的边框、圆角或浅色底，形成“卡片套卡片”。这会让用户先看到组件，而不是看到简历。

处理原则：

- 工作区只保留一条主分隔线；
- 编辑器和预览默认不再各自包一层厚重卡片；
- A4 纸张本身是唯一需要明显边界的对象；
- 圆角只用于真正可操作的浮层、按钮和抽屉，不用于所有容器；
- 阴影最多保留一种低扩散、低对比的纸张层次。

### P0：顶部信息没有主次

简历标题、当前会话、文件名、验收状态、制作步骤和解释文案同时出现，视觉上像“产品在解释自己”。

工作台顶部应收敛为：

```text
校招一页版                         草稿 · 3 个阻断项       打开 Agent
resume.md · 校招标准 · A4
```

制作流程、渲染细节和完整诊断放到相应页面或 Agent 面板，不在主画布首屏重复展示。

### P0：状态色使用过量

成功、注意、阻断和普通信息如果都使用彩色胶囊，会使页面变得嘈杂。状态应先有文字结论，再使用颜色作为弱提示；红色只保留给真正阻止导出的事项。

建议只保留三种等级：

1. 默认：灰色文字，表示当前草稿或已渲染；
2. 注意：暖色文字，表示需要用户确认；
3. 阻断：红色文字或极浅红底，表示不能导出。

### P1：正文和辅助文案不够干净

“Markdown 修改写入当前会话草稿，右侧 A4 预览随模板直接呈现”这类文字适合设计说明，不适合常驻工作台。

默认界面应优先使用短标签和动作词：

- `resume.md · 草稿`
- `校招标准 · A4`
- `3 个阻断项`
- `打开 Agent`
- `重新渲染`

较长解释只在悬浮帮助、诊断结果或 Agent 回复中出现。

### P1：A4 预览仍然需要更强的主画布地位

预览不是一个普通的右侧卡片，而是最终成品。工作台应做到：

- 预览区背景安静；
- 纸张有清晰但不夸张的边界；
- 默认 fit-to-width，优先保证整页可见；
- 不出现页面、面板、iframe 三层嵌套滚动条；
- Agent 打开时压缩主区，不改变 A4 的阅读顺序。

### P1：缺少统一的尺寸和间距系统

当前视觉问题部分来自局部 CSS 逐块调整。建议建立以下最小 token 集，不让 Codex 每次凭感觉改数值：

| 类别 | 推荐基线 |
|---|---|
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 40 / 48 |
| 圆角 | 4（控件）/ 8（操作面板）/ 12（抽屉或浮层） |
| 文字 | 11 / 13 / 14 / 16 / 24 |
| 行高 | 元数据 16、正文 20–22、标题 28–32 |
| 边框 | 1px，低对比；不使用多种灰度边框 |
| 阴影 | 仅纸张或浮层使用一种弱阴影 |
| 主色 | 一种冷静蓝，仅用于主动作与选中态 |

## 推荐颜色与字体基线

这是视觉方向的基线，不是要求一次性重写所有 CSS。

```text
工作区背景  #F6F7F9
次级背景    #EEF1F4
纸张        #FFFFFF
主文字      #17202A
次文字      #667281
弱文字      #98A2AE
主动作      #2F6FED
注意        #B7791F
阻断        #C74634
分隔线      #DDE2E8
```

字体沿用 Demo 已有的 `IBM Plex Sans` / `IBM Plex Mono` 体系：这是对 UI 设计技能中“避免通用字体”的有意约束覆盖，原因是项目已经建立了该字体体系，并且它适合编辑器与元数据场景。不要在局部再混入其他字体。

建议排版层级：

```text
页面/简历标题  24px / 32px / 600
区域标题       14px / 20px / 600
正文           13px / 21px / 400
元数据         11px / 16px / 500
代码/路径      12px / 18px / IBM Plex Mono
```

## Agent 产品的高级感应该怎么落地

成熟 Agent 产品的共同点不是“聊天窗口做得更大”，而是让 Agent 退到任务旁边：

- Codex 的外壳以项目、任务和会话为上下文，中间区域专注当前工作；
- Claude Artifacts 将产物放在聊天右侧的独立区域，聊天负责驱动迭代；
- cdesktop 将 transcript、计划、文件和预览拆成明确的辅助面板。

因此 CVAgent 的 Agent 抽屉需要遵循三条规则：

1. 默认收起，不和简历成品竞争首屏注意力；
2. 打开后只提供当前简历相关的建议、阻断项和输入框，不重复讲工作区概念；
3. 每个 Agent 回复都能落到一个结果或动作，例如“压缩到一页”“应用模板”“重新渲染”，而不是只给解释。

## 不建议继续做的事情

- 不再用大面积渐变、发光、玻璃拟态或装饰性网格制造“AI 感”；
- 不再给每个状态加一个独立胶囊；
- 不再在工作台增加常驻说明卡片；
- 不再用截图要求 Codex 逐像素仿制；
- 不再为了显得专业而缩小 A4 纸张或正文；
- 不再让用户在同一屏同时理解工作区、会话、简历、模板和流程的全部关系。

## 让 Codex 真正调出满意 UI 的交付方式

截图失败的原因，是它只能表达某个时刻的外观，不能表达交互状态、内容密度和不可见的设计约束。后续给工程者的输入应固定为四件事：

### 1. 一页视觉规范

包含方向、色板、字体、间距、圆角、边框和状态规则。所有改动先服从这页规范。

### 2. 四个状态样本

至少提供：

- 默认工作台：Agent 收起；
- 编辑中：Markdown 有改动，预览同步刷新；
- Agent 打开：右侧抽屉展开，主画布仍可读；
- 阻断状态：无法导出，只有一个明确下一步。

### 3. 文字和操作预算

每个首屏区域明确限制：标题数量、状态数量、按钮数量和说明行数。工作台顶部最多一个状态结论、一个主操作；默认说明不超过三行。

### 4. 可验证的验收指标

- 1280×800 下没有页面级横向滚动；
- 关闭 Agent 时，Markdown 和 A4 都保有可读宽度；
- 打开 Agent 时，抽屉宽度稳定，主画布不跳变到不可用；
- 首屏不出现重复的工作区、会话和简历解释；
- 视觉焦点按“标题 → A4 → 下一步动作”排列；
- 只看截图时，用户能判断当前状态和下一步，而不需要阅读长段说明；
- 模板库展示真实渲染缩略图，不能用伪造线框替代。

## 推荐实施顺序

### P0：先收敛视觉语言

统一 token、字体层级、背景灰度、边框和圆角；删除卡片套卡片与重复状态。

### P1：再收敛工作台内容

压缩顶部、减少流程解释、强化 A4 主画布、处理 fit-to-width 和滚动关系。

### P2：最后做细节质感

补齐 hover、focus、loading、empty、error 和成功状态；再微调图标、阴影、动效和模板库缩略图间距。

## 最终判断

应该调研，但调研的对象不是“哪个 Agent 页面更花哨”，而是成熟产品如何控制注意力、状态和视觉噪声。

CVAgent 最适合的基准组合是：

```text
Codex：任务与会话外壳
Claude Artifacts：产物优先、Agent 侧置
Geist：字体与中性色体系
Radix / USWDS：间距、字号和可读性约束
```

这条路线能让现有布局保留，同时去掉“AI 样板感”。高级感的第一步不是增加设计，而是让用户只看到当前真正重要的三件事：简历结果、当前状态、下一步动作。
