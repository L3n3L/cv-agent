# Agent 聊天链路与功能联调测试需求

## 目标

为 CVAgent 建立可重复的 Agent 聊天端到端测试。测试必须验证 MCP 简历工序、SSE 工具事件、聊天时间线、A4 测量与正式保存门是一条连续链路，而不是分别测试 API 或静态 UI。

## 范围

- 从没有历史工作区、会话或浏览器存储的新用户状态开始；
- 从空文件夹创建工作区；在进入前，文件夹中不存在 `resume.md`；
- 用户选择工作区即由 CVAgent 初始化首份隔离草稿，而不额外要求“新建简历”确认；
- 使用脚本化 Agent 回放固定工具调用，不以模型输出作为回归判定；
- 通过真实浏览器验证聊天、工具组、Markdown、A4 iframe 与保存状态；
- 记录截图、浏览器控制台、API 结果和关联日志；
- 真实模型仅作为人工烟测，不进入自动回归。

## 非目标

- 不发送用户真实简历、密钥或聊天内容到第三方模型服务；
- 不把浏览器截图的像素差异作为唯一正确性判据；
- 不为测试增加未经显式启用的生产 API 或测试后门。

## 验收要求

1. 当新用户选择空文件夹并进入工作区时，系统必须自动创建首份隔离草稿与 A4 初始预览；在进入前不得预置 `resume.md` 或会话。初始化完成后，Agent 可立即收集信息并制作简历；正式保存仍不可用。
2. 当脚本化 Agent 执行制作流程时，系统必须以顺序 `prepare → read → check → write → check → render` 记录工具事件，并在浏览器测量后记录 `metrics → finalize`。
3. 当 A4 测量回传的 `renderId` 不是当前 render 时，系统必须拒绝该回传，当前草稿、预览和保存资格不得变化。
4. 当内容、模板或排版变化后，系统必须使旧 render、测量和验收失效；保存按钮必须保持不可用，直到新 render 通过真实测量和 finalize。
5. 当 Agent 面板打开、关闭、刷新并恢复会话时，用户必须仍能看到按发生顺序分组的工具记录，并能展开已完成工具组。
6. 当浏览器在 1280×800 与 1440×900 的验收视口显示工作台时，Agent、Markdown 与 A4 必须是同级区域；任一栏变宽不得遮住另外两栏。
7. 每条联调用例必须输出可定位的证据：场景名、sessionId、runId、renderId、截图、DOM/控制台摘要和服务端日志查询条件。
