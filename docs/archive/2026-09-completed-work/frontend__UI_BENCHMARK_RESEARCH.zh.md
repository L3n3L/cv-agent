# CVAgent Agent 工作台 UI 对标调研

日期：2026-09-17

## 结论先行

当前 Demo 的工作台布局已经基本正确：左侧 Markdown、右侧 A4，Agent 作为右侧辅助面板。

目前“不够高级”的主要原因不是缺少装饰，而是信息没有分层：标题、会话、工作区、制作流程、排版状态、渲染状态和操作提示同时出现，主任务画布被解释性内容挤压，视觉上因此产生明显的“AI Demo 感”。

下一轮不重做信息架构，采用“Codex 的任务上下文 + Claude Artifacts 的产物面板 + cdesktop / PI-Desktop 的工作台密度”作为基准，做信息减法和视觉收敛。

## 参考对象

### 1. Codex：任务和项目是第一层上下文

[OpenAI Codex 官方介绍](https://openai.com/index/introducing-the-codex-app/)

- 左侧承载项目、任务和会话切换。
- 中间区域聚焦当前任务，不把所有能力同时摊开。
- Agent 的运行状态、变更和审查围绕当前任务出现。
- 成熟感来自任务上下文稳定，而不是大量装饰组件。

对 CVAgent 的启发：工作区和会话要稳定存在，但工作台顶部不应该再次解释一遍工作区和会话关系。

### 2. Claude Artifacts：聊天是驱动器，产物是主画布

[Claude Artifacts 官方说明](https://support.claude.com/en/articles/9487310/what-are-artifacts-and-how-do-i-use-them)

- 较大的产物放在聊天右侧的独立窗口。
- 产物可以直接编辑、迭代和切换版本。
- 聊天不是页面主体，而是对产物的操作入口。

对 CVAgent 的启发：A4 成品必须是工作台的主要视觉对象；Agent 只在需要解释、提出修改或生成候选时出现。

### 3. Cursor：Agent 侧栏化，主界面围绕任务结果

[Cursor Agent 官方文档](https://cursor.com/docs/agent/overview)

- Agent 以侧栏 / side pane 形式出现。
- 工作区、文件和 Agent 任务属于同一个项目上下文。
- 用户可以在不离开主工作区的情况下继续审阅和修改。

对 CVAgent 的启发：Agent 抽屉关闭时，编辑和预览应该完整占据空间；打开时只压缩主区，不改变工作流。

### 4. cdesktop：接近 CVAgent 的开源工作台模型

[cdesktop GitHub](https://github.com/cdesktop-ai/cdesktop)

- 会话侧栏、任务 transcript、右侧计划 / 文件 / 预览面板是明确分工的三个层级。
- 预览、终端、diff 等属于补充面板，不和主任务信息混在一起。
- 会话切换不会丢失上下文。

对 CVAgent 的启发：不要把“当前会话说明”“操作提示”“预览状态”都做成独立卡片；它们应该分别落在会话列表、主编辑器标题和预览标题中。

### 5. PI-Desktop：长期工作台而非一次性聊天窗口

[PI-Desktop GitHub](https://github.com/vastsa/pi-desktop)

- 项目、会话、文件、评审、预览和 Agent 工作保存在同一工作区。
- 主流程是打开项目 → 选择 Agent / Plan / Goal → 查看结果 → 审阅。
- 说明文本较少，靠稳定的空间和状态结构让用户理解产品。

对 CVAgent 的启发：工作区是稳定容器，简历、模板、会话和成品都在容器内；页面不要反复讲概念关系。

## 成熟 UI 的共同模式

| 维度 | 成熟 Agent 产品 | 当前 Demo | 判断 |
|---|---|---|---|
| 左侧 | 项目 / 工作区 / 会话 | 已有工作区和会话 | 基本正确 |
| 主画布 | 当前任务或产物 | Markdown + A4 | 基本正确 |
| Agent | 按需侧栏 | 已改为抽屉 | 方向正确 |
| 顶部 | 一个上下文标题 + 少量主操作 | 标题、状态、文件、流程、步骤并列 | 信息过量 |
| 状态 | 一个明确结论和下一步 | 多个状态标签重复表达 | 需要合并 |
| 视觉 | 少边框、强层级、低噪声 | 面板套面板、边框偏多 | 需要收敛 |
| 文案 | 短标签、动作导向 | 解释句较多 | 需要删减 |
| 响应式 | 主画布优先，辅助区自动收纳 | 窄屏容易出现嵌套滚动 | 需要补规则 |

## 当前 Demo 的具体问题

### A. 顶部有四层“解释”

当前同时显示：

1. 当前会话 / 工作台
2. 简历标题和验收状态
3. 文件元信息
4. 制作流程和内容 / 排版 / 保存步骤

用户真正需要的只有：

> 校招一页版 · 草稿 · 3 个阻断项

以及一个主动作：

> 打开 Agent 或继续编辑

### B. 状态没有形成行动结论

“草稿”“需要重新验收”“待测量”“2 页 / 目标 1 页”分散在不同位置。

应该收敛成一个状态句：

> 暂不能导出：当前 2 页，存在 3 个排版阻断项。下一步：压缩项目经历。

### C. 面板边界太多

侧栏、主区、编辑器、预览区和 iframe 都有自己的边框与圆角，造成“组件展示”感。

建议：

- 编辑器和预览保留一条轻分隔线即可；
- 只给需要操作的区域保留容器边界；
- A4 纸张本身承担视觉焦点，不要再给它叠多层卡片。

### D. 文案偏像产品说明书

例如“Markdown 修改写入当前会话草稿，右侧 A4 预览随模板直接呈现”是设计说明，不是用户当前需要的操作信息。

工作台默认只保留短文案：

- `resume.md · 草稿`
- `校招标准 · A4`
- `3 个阻断项`

详细解释放到 Agent 回复、排版检查页或悬浮提示中。

### E. 缩放策略还不够像成熟编辑器

预览应优先 fit-to-width，而不是让 A4 固定尺寸后产生内部滚动。窗口变窄时，优先降低纸张缩放，继续保证整页可见；再窄时才收起预览或 Agent。

## CVAgent 推荐基线

不直接复制某一个产品，而是采用以下组合：

```text
左侧：Codex 的项目 / 会话上下文
中间：编辑器 + 成品预览主画布
右侧：Claude Artifacts / cdesktop 式按需 Agent 面板
状态：PI-Desktop 式短状态 + 明确下一步
```

### 工作台默认状态

- 左侧继续保留 CVAgent、工作区、模板库、排版检查、投递版本和会话。
- 顶部只保留简历名称、一个状态结论、一个 Agent 入口。
- 中间默认左 Markdown、右真实 A4。
- Agent 默认收起。
- 不在工作台默认展示完整运行日志、长解释和重复状态。

### Agent 打开状态

- 右侧固定宽度抽屉，宽度约 320–360px。
- 抽屉标题只显示 `Agent 助手` 和当前会话。
- 首屏显示最近任务、当前阻断项和一个输入框。
- 旧消息可以滚动，但不能把编辑器和 A4 挤到不可读。

### 状态层级

只保留三种视觉等级：

1. 正常：当前草稿 / 已渲染
2. 注意：待重新渲染 / 待用户确认
3. 阻断：不可导出 / 3 个排版问题

## 下一轮验收标准

- 1280×800 下，关闭 Agent 时 Markdown 和 A4 都不出现页面级横向滚动。
- 打开 Agent 后，主区仍保留可读的编辑区和 A4 结果。
- 顶部除标题外最多出现一个状态标签和一个主操作。
- 首屏不重复出现“当前会话 / 当前工作区 / 当前简历”的解释。
- 默认可见的说明文案不超过 3 行。
- 用户可以只看 A4、只改 Markdown，或按需打开 Agent，不必切换模式。
- 模板库只展示缩略图；完整结果只在 A4 预览中展示。

## 最终建议

当前不需要推翻布局，也不建议继续堆功能。下一轮应做一次“去 AI 味”的视觉收敛：删文案、并状态、减边框、压缩顶部、提高主画布占比、统一按钮层级和 A4 缩放策略。

这会比增加渐变、阴影、装饰图标或更多卡片更接近 Codex、Claude 和成熟 Agent 工作台的质感。
