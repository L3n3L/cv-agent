# Agent 聊天数据流治理需求

更新：2026-09-19  
状态：基础回放能力已实现，多轮 turn 归并和旧链路退役未完成

## 1. 问题定义

CVAgent 的聊天同时依赖会话消息快照、工作流事件和前端乐观状态。生产模式在渲染后会暂停等待真实 A4 测量，SSE 还需要支持断线重连和历史回放。当前多个状态源之间没有稳定的事件序号和轮次身份，导致暂停后消息回退、重连后流式文本缺失、自动 continuation 覆盖当前快照等问题。

## 2. 用户故事

- 作为用户，我希望 Agent 暂停等待 A4 测量时，刚刚发送的消息和 Agent 已经生成的回答仍然留在会话中。
- 作为用户，我希望 SSE 短暂断开并自动重连后，聊天时间线能够从断点继续，不重复、不漏掉工具记录。
- 作为用户，我希望刷新或恢复会话时，最终消息、工具轨迹和当前简历状态保持一致。
- 作为维护者，我希望每个工作流事件都有稳定的 session、run、turn 和 sequence 标识，可以从日志追踪完整链路。

## 3. 验收标准（EARS）

### REQ-1 会话消息一致性

- 当用户提交一条消息时，系统应在 Agent 执行开始前将该用户消息纳入当前 session 的可恢复状态。
- 当 Agent 在正常完成、暂停等待测量或提前完成分支结束时，系统应保存已经获得的最终消息结果；如果模型没有返回结果，也不得覆盖已经保存的用户消息。
- 当客户端收到暂停或失败终态时，系统应保留当前轮的可见消息，不能用旧 session 快照覆盖当前轮。

### REQ-2 事件身份与回放

- 当后端发布工作流事件时，系统应为该事件分配 session 内单调递增的 sequence。
- 当浏览器首次连接 SSE 时，系统应回放当前 session 的可用事件；当浏览器携带 Last-Event-ID 重连时，系统应只回放该序号之后的事件。
- 当同一事件同时来自 bootstrap 快照和 SSE 回放时，前端应按稳定 sequence 去重，而不是依赖时间戳和文本内容。

### REQ-3 前端归并

- 当事件进入前端时，系统应按稳定事件身份归并工具调用和 assistant 消息，不得按工作流数组位置猜测对话归属。
- 当当前流式文本已经在内存中累积但部分 delta 事件被截断或重连遗漏时，系统应优先保留当前轮可见文本。
- 当多个 Agent 终态连续到达时，系统应保证最终一次同步不会被更早的同步请求覆盖。

### REQ-4 回归与诊断

- 当执行 paused、failed、自动 continuation、SSE 重连和长事件流测试时，系统应保留可复现的 session/run/sequence 证据。
- 当现有 UI 和 API 不涉及数据流语义时，不得借本次治理重写布局或删除历史诊断事件。

### REQ-5 架构收敛与旧链路退役

- 当新数据流或新 renderer 替代旧实现并通过迁移测试后，系统应删除旧调用路径、旧关联逻辑和永久性兼容分支，不得让两套实现继续成为事实来源。
- 当新增临时兼容逻辑时，工程记录应同时声明替代目标、删除条件、影响范围和验收测试；没有删除条件的兼容逻辑不得合入主链路。
- 当 P0 数据流重构尚未完成时，系统不得以增加 UI 分支、状态文案或 fallback 的方式掩盖消息归属和执行终态问题。
- 当工具调用失败时，系统应保证该 run 进入明确的 failed 终态；不得依赖服务重启、页面刷新或 session 恢复逻辑结束一个仍显示 running 的 run。
- 当前处于开发阶段时，数据模型切换前应清空旧开发 session；系统应保留工作区源文件、模板、渲染产物和诊断日志，不要求兼容旧 session 的聊天历史。

### REQ-6 工具过程折叠呈现

- 当一个 turn 包含工具调用时，系统应将工具调用作为该 turn 内的可展开过程轨迹，默认收起，不将每一项工具平铺为独立聊天消息。
- 当工具仍在执行时，系统应在收起状态显示轻量渐变或呼吸动效；动效只表示当前执行状态，不得伪造工具完成结果。
- 当用户展开工具过程时，系统应按 sequence 展示真实工具名称、耗时、结果摘要和失败状态。
- 当工具完成、暂停或失败时，系统应停止执行态动效并显示稳定的真实终态。
- 当页面刷新或 SSE 重连时，系统可以恢复工具过程为默认收起，但不得丢失工具结果、错误码或 run 终态。

## 4. 范围外

- 不改变 Agent 工具权限策略和简历生产业务状态机。
- 不重做聊天视觉样式，不引入新的 UI 框架。
- 不把私有 chain-of-thought 写入前端或持久化协议。
- 不要求一次性解决跨多实例部署的分布式消息代理问题；本阶段仍以单进程 session broker 为运行边界。
