# Presentation 与模板工作台：需求与对接复盘

## 1. 目标

本期补齐两个已有领域能力的产品闭环：

1. 用户可以安全地微调当前简历的呈现参数；
2. 用户可以在当前工作区浏览、派生、创建、迭代与恢复模板。

两者共用同一份 A4 渲染和真实浏览器测量，但资产边界不同：presentation 是当前简历的隔离覆盖，模板是可复用、可修订的工作区资产。

## 2. DSH 对接结论

DSH 的 `presentation_save`、`template_autotune`、`template_generate`、`template_save`、`template_versions`、`template_restore` 与 `layout_save` 定义了完整领域契约。CVAgent 已迁入其中的受控生成、保存、修订、恢复、presentation 覆盖、结构校验和验收门；不迁入 DSH 的宿主工具、全局工作区状态或插件 UI。

当前缺口是产品层，而非缺少基础能力：

- A4 面板尚未对标 DSH 的完整手动微调：字体选择、滑杆即时预览、布局撤销、默认恢复，以及基于当前 A4 图标库存的逐图标调整；
- 模板库只支持浏览和选择，未展示来源、修订、派生关系、历史恢复或创建入口；
- Agent 可生成候选，但候选到用户确认保存的工作台入口不完整。

## 3. 用户故事

1. 作为用户，我可以只调当前简历的字体、间距与实际出现在 A4 中的图标，不意外改动模板或正文。
2. 作为用户，我可以一键恢复当前简历到模板默认呈现，并知道这会要求重新 A4 验收。
3. 作为用户，我可以识别模板是官方模板还是我的工作区模板、其当前修订和来源模板。
4. 作为用户，我可以复制官方/已有模板后，在自己的工作区继续迭代而不破坏原模板。
5. 作为用户，我可以查看自定义模板历史，并把某个历史修订恢复成新的当前修订。
6. 作为用户，我可以从模板库发起一个受约束的设计 Brief，先审阅候选，再明确保存为自己的模板。

## 4. 业务规则

- 滑杆与撤销先写入浏览器内存中的 presentation draft，并立即注入当前 A4 iframe；只有“应用到当前草稿”才写入当前会话中当前简历的 resume-scoped override。两者均不得创建模板文件、模板修订或修改简历正文。
- 每次 presentation、模板选择、模板恢复或模板保存后，旧 render 与旧测量必须失效；必须重新渲染并使用新 renderId 测量。
- 内置模板不可修改；结构/CSS 改造必须先复制为工作区模板。
- 模板候选仅存在于内存，直到用户明确点击“保存为我的模板”。
- 恢复历史模板生成递增的新修订，而非倒退或覆写历史。
- 模板库不会因“保存候选”或“恢复其他模板”静默替换当前会话模板；选择模板仍是显式动作。
- 视觉参数不越过后端的范围与颜色校验；不提供任意 CSS、HTML 或 JavaScript 输入。

## 5. 验收标准

1. 当用户打开手动微调时，系统应展示字体和排版滑杆、从当前 A4 iframe 扫描得到的图标滑杆、撤销与恢复默认操作；视觉 Token 仅属于模板工坊。
2. 当用户调整微调控件时，系统应先即时更新 A4 与本地草稿；当用户应用草稿时，系统才提交 presentation 覆盖、重新渲染当前草稿，并显示等待真实 A4 测量的状态。
3. 当用户恢复默认时，系统应仅将本地草稿恢复为模板默认；应用后才移除当前简历的相应 presentation 覆盖，且不创建模板修订或修改正文。
4. 当用户进入模板库时，系统应显示模板来源、当前修订、派生来源和当前使用状态。
5. 当用户打开自定义模板历史时，系统应列出不可变修订；确认恢复后，系统应显示新的递增修订。
6. 当用户发起新模板时，系统应先生成经校验的候选并显示质量审计；未确认保存前，该候选不得出现在模板库。
7. 对以上所有影响预览的操作，真实浏览器截图应证明 A4 iframe 已刷新；首方页面资源不应产生新的控制台错误。

## 6. 非目标

- 多用户共享、云端模板市场或跨工作区模板同步。
- 任意布局拖拽和自由 CSS 编辑器；`layout_save` 在未来的模板设计器阶段再产品化。
- Agent 自动接受或静默保存模板候选。
