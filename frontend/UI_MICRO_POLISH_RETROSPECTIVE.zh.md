# CVAgent 工作台 UI 微调对接复盘

> 目标：在不改变 Markdown、A4、Agent 三栏布局和业务交互的前提下，统一工作台的视觉边界、空间节奏和层级表达。
>
> 当前基线：`fb8e2e8 fix: make workbench dividers visually adjacent`
>
> 本文是后续 Codex/CVAgent 继续修改 UI 时的执行依据。任何改动都应先对照本文，避免重新引入“每个区域都是一张矩形卡片”或“编辑区没有边界”的问题。

## 1. 当前问题复盘

当前布局方向是正确的：左侧导航、Markdown 编辑、A4 预览、Agent 面板已经形成了稳定的工作台结构。突兀感主要来自视觉系统没有收敛，而不是来自列布局。

### 1.1 边界表达不一致

- `editor-pane`、`direct-preview-pane` 在后续覆盖中被去掉圆角和外框，但编辑区只留下右侧分隔线，导致 Markdown 区域像一块没有边界的空白。
- A4 预览同时拥有预览标题、灰色舞台、白纸和纸张阴影，层级完整；Markdown 和 Agent 没有对应的“工作面”层级。
- 页面、面板、内部分组同时使用背景色、边框、分隔线和阴影，但没有明确强弱关系。

### 1.2 分隔器占位制造了可见空带

实际问题不只是颜色或圆角：三栏网格把侧栏、Markdown、A4 和 Agent 之间的拖拽分隔器定义成了 `8px` 的独立列。虽然分隔器本身是透明的，但这 8px 仍然参与布局，于是模块之间出现了肉眼可见的空白带，尤其是在桌面宽屏和 Agent 拉宽时最明显。

这和目标交互不一致。Codex 式工作台的区域是直接相邻的，中间只表达一条克制的边界线；拖拽需要的是透明的命中热区，而不是一块可见的空栏。本次统一修正为：

- 网格中的视觉分隔列固定为 `1px`；
- 分隔器本体只绘制 `1px` 浅色竖线；
- 通过 `::after` 向两侧扩展透明的 `9px` 拖拽命中区，不改变用户可拖拽能力；
- 分隔线默认可见，悬停或拖拽时只略微加深；
- 编辑器、A4 和 Agent 仍是同级网格项，不使用绝对定位互相覆盖；
- 窄屏堆叠时，隐藏的分隔器也不再保留 8px 的空行。

### 1.3 工作面内部外边距过大

上一轮已经收掉了模块之间的可见分隔器空带，但截图表明问题还存在于每个模块自身：

- Markdown 的 `.editor-layout` 使用了 `28px` 左右内边距，编辑区被两侧白边明显挤窄；
- A4 的灰色预览舞台使用了 `22px` 顶部和 `20px` 水平内边距，纸张外侧形成了不必要的灰色框；
- 编辑器和预览底栏的水平、垂直 padding 也偏大，进一步减少了真正工作面的高度；
- 这些空间不是简历纸张的内部页边距，不能通过修改模板的 `pageMargin` 来解决。

本轮以用户提供的工作台截图为视觉基线：

- Markdown 工作面尽量铺满面板，保留 `16px` 的标题、编辑文字和底栏阅读内边距；
- A4 舞台只保留 `8px` 的纸外呼吸边，纸张内部页边距仍由模板和渲染器负责；
- 底栏保留状态和操作，但收敛到必要高度；
- 不改变 Markdown/A4/Agent 三个模块之间的 1px 分隔线，也不改变 A4 fit-to-width 计算。

### 1.4 CSS 覆盖历史导致视觉漂移

`styles.css` 中存在基础样式、视觉精修样式、Agent 专属样式和响应式修正多轮覆盖。同一个组件的 padding、background、border 和 radius 分散在不同位置，后续微调容易只修一处而被末尾规则覆盖。

本轮不做全量 CSS 重写，但新增规则必须放在对应的视觉收口区，并同步更新契约测试；后续应逐步把 token 和组件规则收敛到单一来源。

## 2. 对标结论

Codex 的公开产品定位是 Agent 工作指挥台：项目、线程、任务和过程审阅是稳定上下文，工具执行进入任务流，而不是被包装成互相竞争的大卡片。见 [Introducing the Codex app](https://openai.com/index/introducing-the-codex-app/)。

公开的 Codex TUI 源码也采用已提交 transcript cell 与当前活动 cell 的分层，工具过程在活动内容中实时更新。它可以作为“连续过程流”的结构参考，但不等同于 Codex Desktop 的私有 CSS 或源码。见 [Codex TUI ChatWidget](https://github.com/openai/codex/blob/main/codex-rs/tui/src/chatwidget.rs)。

因此 CVAgent 采用以下原则：

1. 整个页面是一个工作台外壳，不是三张并排卡片。
2. Markdown、A4 和 Agent 直接相邻；模块之间只保留 1px 分隔线，不保留可见空带。
3. 主要区域通过背景和细分隔线建立关系，只有真正浮起的产物使用阴影。
4. Markdown 是文档工作面，A4 是结果工作面，Agent 是过程工作面。
5. Agent 工具执行保持时间线和可展开 Item，不增加大块状态卡片。
6. 圆角只用于外层工作台、Composer、按钮等交互面；主工作面不使用明显圆角。

## 3. 视觉契约

### 3.1 边界层级

| 层级 | 使用位置 | 视觉表达 |
| --- | --- | --- |
| 强边界 | 整个 `app-shell` | 单一外框、轻微圆角、极弱阴影 |
| 中边界 | Markdown / A4 / Agent 之间 | 1px 浅色垂直分隔线 |
| 弱边界 | 标题、状态、底栏、工具组 | 极浅横线、左侧轨道或留白 |

禁止给三个工作面同时加深色边框、圆角和阴影。

### 3.2 工作面角色

- Markdown：白色文档面；标题、编辑内容、底部操作形成一个完整的文档节奏；不再依赖内部 textarea 边框。
- A4：浅灰预览舞台 + 白色纸张 + 轻微纸张阴影；舞台本身不做厚重卡片。
- Agent：白色过程流；顶部标题栏正常占位；工具组用左轨道和折叠行表达层级；Composer 是主要交互容器。

### 3.3 间距节奏

只使用 4px 基础节奏：

```text
4px   图标与文字
8px   同组元素
12px  标题与正文
16px  标题、编辑文字和底栏的阅读边距
24px  模块之间
32px  页面级边距
```

三个工作面的标题起始线、底部操作区和内容边距应尽量对齐。

### 3.4 色彩规则

- 页面画布：`#f6f7f9`
- 工作面：`#ffffff`
- 工作面分隔线：`#e5e8ec`
- 内容弱线：`#eef0f2`
- 主文字：沿用现有 `--ink`
- 次文字：沿用现有 `--muted`
- 蓝色不作为大段正文或普通元数据的强调色；只保留在必要的主要动作或既有简历视觉基线中。

## 4. 实施顺序

### 第一阶段：统一外壳与工作面

- 为整个工作台建立单一外框。
- 保留三栏同级关系。
- 将可见分隔列从 `8px` 收口为 `1px`，透明扩展拖拽热区。
- 统一工作面背景和中边界。
- 修复 Markdown 区域“没有边界”的感受。
- 不改三栏宽度计算、A4 fit-to-width 和 Agent 抽屉行为。

### 第一阶段补充：收紧模块内部工作面

- Markdown 编辑区不再使用 28px 的父级水平留白；
- A4 灰色舞台只保留必要的 8px 纸外边距；
- 不把纸外灰色区域误判为简历纸张内部页边距；
- 通过真实浏览器截图确认编辑区、纸张和底栏的可用面积。

### 第二阶段：统一标题与底栏

- 对齐 Markdown、A4、Agent 顶部标题的高度和内边距。
- 让 Markdown 底部操作、A4 测量状态、Agent Composer 各自成为稳定的底部锚点。
- 减少重复状态文案，不新增装饰性标签。

### 第三阶段：过程流微调

- 保持工具组可展开、可收起。
- 工具组使用左侧弱轨道和行间距表达归属。
- 仅调整密度、颜色和分隔，不改事件数据和会话恢复逻辑。

## 5. 截图验收矩阵

每轮 UI 改动必须在真实浏览器截图验收：

| 视口 | 必查内容 |
| --- | --- |
| 1600×1000 | 三栏是否融合；A4 是否完整；Agent 标题和 Composer 是否在正常流中 |
| 1280×800 | Markdown 是否仍可读；A4 是否被压缩而非覆盖；Agent 是否出现硬边框堆叠 |
| 1091px 左右 | 三个工作面是否仍为同级；是否出现重叠或横向滚动 |
| 拖拽分隔器 | 模块是否直接相邻；默认是否只有 1px 线；透明热区能否拖动，不产生可见空带 |
| Agent 展开、工具组展开 | 标题、正文、工具 Item、Composer 是否有明确但克制的层级 |

验收要求：

- 不出现模块互相覆盖；
- 不出现由拖拽分隔器产生的 8px 可见空白带；
- 不出现页面级横向滚动；
- Markdown 有可感知边界但不是厚重卡片；
- A4 纸张边界明显，预览舞台不抢主体；
- Agent 工具流程不会被堆到聊天末尾；
- 控制台无新增错误；
- 现有前端契约测试全部通过。

## 6. 不做的事情

- 不复制 Codex Desktop 私有源码或声称复刻其内部实现。
- 不引入 `codex-webui` 作为组件基线。
- 不全量重写前端框架。
- 不为了“有设计感”增加渐变、霓虹色、重阴影、装饰性图标或更多卡片。
- 不通过改变 A4 尺寸、grid 算法或 Agent 绝对定位来掩盖视觉问题。
