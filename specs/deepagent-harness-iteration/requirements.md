# DSH → DeepAgent 原生对接需求

更新时间：2026-09-19

## 问题

CVAgent 已经有 DSH 对齐的简历生产契约，但规则仍分散在总提示词、`resume_production_guide` 和服务端工具门禁中。继续追加提示词会造成上下文膨胀、规则重复和版本漂移，也无法体现 DeepAgent 原生的 Skill 生态。

## 目标

在不改变当前工作台、模板、渲染和真实测量业务契约的前提下，让 Agent 的领域能力按 DeepAgent 原生 Harness 分层：系统提示词负责稳定原则，Skill 负责可复用领域知识，工具负责业务动作，Middleware/服务端状态负责确定性边界。

## 用户故事

- 作为简历用户，我希望 Agent 能按 DSH 的成熟简历生产流程持续推进，而不是遇到非关键缺口就反复询问。
- 作为产品维护者，我希望 DSH 的简历规则只有一个可追踪的 Skill 来源，避免提示词、工具说明和实现各自漂移。
- 作为系统开发者，我希望普通聊天和只读检查不加载生产规划与写入能力，生产任务才启用对应 Skill 和规划能力。
- 作为验收人员，我希望真实渲染、当前 `renderId`、逐页测量和 `resume_finalize` 仍由确定性业务门禁控制，不能被模型文字绕过。

## EARS 验收标准

1. 当请求被识别为简历生产模式时，系统应通过 DeepAgent 原生 `skills` 机制暴露 `resume-production` Skill，并把 Skill 文件作为当前 Agent 状态提供，而不是把完整 DSH 契约继续拼进总提示词。
2. 当请求是普通聊天时，系统不应启用简历生产 Skill、`write_todos` 或简历工具面。
3. 当请求是只读检查时，系统应只暴露读取、检查和查询工具，不得因为 Skill 或提示词导致写入、渲染、模板修改或正式保存。
4. 当生产 Agent 修改内容、模板或 presentation 后，系统应继续要求当前版本重新检查、渲染、真实测量和 `resume_finalize`，旧 `renderId` 的指标不得通过验收。
5. 当用户未提供岗位或 JD 时，生产 Skill 应指导 Agent 制作通用投递版，而不是把非关键缺口升级为必须提问。
6. 当模型试图声明完成但当前 `resume_finalize` 未返回 `accepted=true` 且 `completionAllowed=true` 时，系统应阻止完成状态和正式保存。
7. 当 Skill 文件的内容或路径失效时，系统应在启动生产 Agent 前报出明确错误，不得静默执行无契约生产流程。

## 非目标

- 不把所有用户消息固化为统一的自动多轮循环。
- 不把真实测量和保存授权交给提示词自觉执行。
- 不改变当前 A4 模板视觉结构、工作区存储或前端聊天展示契约。
- 不在本轮引入新的远程 Skill 仓库或让 Agent 获得宿主仓库文件访问权限。
