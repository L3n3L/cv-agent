# Agent 对话 Codex 对齐调研与重构决策

> 结论：当前 Agent 对话仍然是“AI 聊天组件”，需要改成“任务过程文档流”。  
> 本文覆盖并修正 `AGENT_CHAT_UI_REFINEMENT.zh.md` 中关于头像、气泡和颜色的旧建议。  
> 范围：只改 Agent 抽屉的视觉结构与渲染表达，不改 Agent 协议、会话行为、简历渲染和工具调用。

## 1. 这次调研得到的关键结论

### 1.1 Codex 的聊天不是传统聊天产品

OpenAI 对 Codex 的公开定位是 Agent 的工作指挥台：用户在项目和任务线程中监督 Agent 的工作、查看结果并继续协作。[Introducing the Codex app](https://openai.com/index/introducing-the-codex-app/)

这决定了对话区域的重点不是“谁在说话”，而是：

- Agent 当前完成了什么
- 中间调用了哪些工具
- 结果是否可验证
- 用户下一步能否继续推进

公开资料没有披露 Codex 的完整前端组件源码，因此像“无头像、无彩色气泡、工具过程是轻量节点”属于基于用户提供的 Codex 截图和产品定位做出的视觉归纳，不声称是官方 CSS 规则。

### 1.2 用户截图呈现的是“排版优先”的工作流

截图中可以观察到几个稳定特征：

1. 大面积白底和深灰正文，几乎没有角色色彩。
2. 不使用用户头像或 AI 头像。
3. 主要内容以连续文本流出现，不给每条消息套一个大气泡。
4. 工具动作以低对比度的过程节点出现，例如“编辑了文件”“运行了命令”。
5. 运行时反馈用极轻的渐变/状态变化表达，不长期保留高饱和色块。
6. 时间和耗时是辅助信息，不应该和正文抢层级。

### 1.3 对 CVAgent 的直接启示

简历制作是一个有明确产出的 Agent 工作流：读取简历 → 检查内容 → 修改草稿 → 渲染模板 → 排版验收。因此 Agent 抽屉应该像一条可读的“制作记录”，而不是客服式对话。

## 2. 对上一版方案的纠偏

上一版虽然降低了卡片和颜色，但仍保留了以下 AI 聊天痕迹：

- `A` / `L` 角色头像
- `CVAgent` / `你` 重复角色名
- 每条消息的时间戳
- 用户浅蓝气泡
- Agent 与用户消息的显式颜色区分
- 大块 `run-card` 状态组
- 红色阻断文字和蓝色操作按钮同时出现在抽屉中

这些元素单独看都能用，但叠在一起就会变成“标准 AI 对话模板”，和用户给出的 Codex 参考相反。

新的决策是：

| 元素 | 新决策 |
| --- | --- |
| 用户 / AI 头像 | 删除；身份通过消息顺序和语义理解，视觉上不再标注 |
| 角色名 | 默认隐藏；保留无障碍文本或 DOM 语义，不做视觉标题 |
| 时间 | 只保留会话节点或工具组一次，不逐条重复 |
| Agent 消息 | 纯正文流，无灰色气泡 |
| 用户消息 | 纯正文流，无蓝色气泡；可以用微小的上下间距区分段落 |
| 运行状态 | 改成工具过程节点，轻分割线 + 小型状态文本 |
| 阻断状态 | 对话内不使用红色；顶部工作台状态继续负责表达阻断 |
| 操作按钮 | 采用无背景文字操作，默认深灰，hover 才变化 |
| 输入区 | 中性白色输入面板；不使用蓝色发光、蓝色底色或大阴影 |
| 动效 | 只给运行中的工具节点使用中性灰渐变扫光，完成后停止 |

## 3. 目标视觉结构

```text
Agent                                                        收起
校招一页版 · 当前草稿
─────────────────────────────────────────────────────────────

已载入当前简历和校招标准。可以修改内容、版式或生成投递版。

把实习经历改成更偏 AI 产品经理的投递版，并尽量压到一页。

已处理 12 秒
    编辑了简历草稿
    读取了校招标准
    检查了页面密度
    排版验收未通过                         2 页 / 目标 1 页

当前有 3 个排版阻断项。先压缩项目经历，再重新渲染。
采纳建议                 打开预览

─────────────────────────────────────────────────────────────
描述你要怎么改，例如：把实习经历改成 AI 产品经理投递版
                                                   发送
```

这里没有头像、气泡、彩色状态徽章和重复角色名；用户仍然能够通过内容顺序理解过程，工具执行节点提供可验证的进度。

## 4. 设计规格

### Purpose Statement

让用户专注于简历修改结果和 Agent 的实际工作过程。对话窗口只呈现必要的正文、工具过程和下一步操作，不重复工作台顶部已经表达的会话、模板和阻断信息。

### Aesthetic Direction

`Brutally minimal` 与 `Luxury / refined` 的交叉方向：白底、黑灰文字、极少分割线，靠排版节奏和短暂动效表达产品质感。

### Color Palette

对话抽屉内部只允许使用以下颜色：

- 正文：`#17202A`
- 次正文：`#667281`
- 辅助信息：`#98A2AE`
- 分割线：`#E8EBEF`
- 输入底：`#FFFFFF`
- 抽屉背景：`#FBFCFD`

不在 Agent 抽屉内使用：

- `--blue`、`--blue-soft`
- `--red`、`--red-soft`
- 用户气泡色
- 彩色头像背景
- 任何紫色、蓝紫渐变或彩色状态点

工作台顶部的蓝色操作和红色阻断状态可以保留；它们属于工作台全局层，不属于聊天内容层。

### Typography

- 正文：`IBM Plex Sans`, `Microsoft YaHei`, sans-serif
- 耗时、工具名、辅助状态：`IBM Plex Mono`, monospace
- Agent 正文 12px，用户正文 12px，工具状态 10px，耗时 9px
- 不通过加粗和大字号反复强调 Agent 身份

### Layout Strategy

采用垂直文档流：标题区 → 单行会话上下文 → 正文流 → 工具过程节点 → 最新建议与操作 → 固定底部输入区。消息不以对称左右气泡呈现，不使用居中卡片，也不做角色色块。

## 5. 具体实施规则

### 5.1 抽屉头部

- `按需辅助`删除。
- `Agent 助手`改为 `Agent`。
- `收起`保留为右上角普通文字操作。
- 上下文只保留一行：`校招一页版 · 当前草稿`。
- `仅作用于当前会话`可以保留为 9px 灰色辅助文字，但不得形成卡片。

### 5.2 正文消息

- 从 `renderChat()` 和动态发送消息中移除头像节点。
- 从视觉上隐藏 `.message-author`；如需保留可访问性，使用屏幕阅读器专用文本。
- 移除所有 `.message-bubble` 的背景、边框、圆角和大内边距。
- Agent 和用户正文统一左侧起始线，使用段落间距而不是左右对齐制造差异。
- 消息之间约 18px，正文行高 1.6。
- 时间只在会话分隔处保留一次，或改为工具组耗时。

### 5.3 工具执行节点

- `run-card` 不再是卡片；背景透明、边框只保留 1px 极浅左线。
- 状态行不使用圆形徽章；使用小型文本节点或细圆点。
- 完成态全部使用灰色；阻断态也使用深灰文本，详情由工作台顶部红色状态表达。
- 运行中的节点增加一次或循环极慢的中性扫光：

```css
.run-card.is-running::before {
  content: "";
  position: absolute;
  inset: 0 auto 0 0;
  width: 28%;
  background: linear-gradient(90deg, transparent, #e4e7eb, transparent);
  animation: agent-tool-scan 1.8s ease-in-out infinite;
}

@keyframes agent-tool-scan {
  from { transform: translateX(-120%); }
  to { transform: translateX(420%); }
}
```

这是唯一允许在对话内容中出现的渐变；它只用于表示工具正在运行，完成后应移除 `is-running`，不留下持续动画。

### 5.4 操作

- `采纳建议`和`打开预览`使用无背景文字按钮。
- 默认颜色为 `#667281`，hover 使用 `#17202A`，不使用蓝色。
- 操作只挂在最新 Agent 正文下，其他消息不重复显示。
- 点击行为保持现有 `data-suggest` 和 `data-open-preview`。

### 5.5 输入区

- 输入框保留白底、1px 灰色边框、6px 圆角。
- 取消蓝色 focus 光晕和明显阴影，focus 只加深边框。
- 删除“当前草稿 · 修改后需重新渲染”重复提示。
- 发送按钮使用无背景深灰文字；hover 时加深，不要再用蓝色实心按钮。
- 输入区固定在抽屉底部，只有消息流滚动。

## 6. 验收指标

- [ ] Agent 抽屉内不出现用户或 AI 头像。
- [ ] Agent 抽屉内不出现蓝色用户气泡、红色阻断文字或彩色状态圆点。
- [ ] 消息角色名不作为视觉标题重复出现。
- [ ] 工具过程节点没有大面积背景卡片。
- [ ] 运行中工具节点有中性渐变扫光；完成后动效停止。
- [ ] 输入框和发送操作首屏可见，不需要先滚到底部。
- [ ] 只有 `.chat-stream` 滚动，抽屉整体不产生第二条滚动条。
- [ ] 1280×800 和 1440×900 下，文本、工具节点、输入区均不发生遮挡。
- [ ] 发送消息、采纳建议、打开预览和收起 Agent 行为不回归。
- [ ] 工作台顶部的会话标题、模板信息、蓝色操作和红色阻断状态仍然可见。

## 7. 这轮明确不做

- 不复制 Codex 的内部源码或不可验证的实现细节。
- 不重新设计左侧导航、MD 编辑区和 A4 预览区。
- 不把对话改成新的全屏路由。
- 不新增模型选择、能力标签、AI 状态徽章或装饰图标。
- 不用截图做像素级复制；截图只作为层级、颜色和密度的验收参考。

## 8. 复核修正：不能把 Codex 简化成“无气泡聊天”

本轮重新对照 Codex 的公开产品说明、App Server 对话原语，以及实际多轮任务界面后，修正上一版结论：Codex 并不是所有消息都取消气泡，而是根据内容类型采用不同表达。

### 8.1 Codex 的核心不是“气泡有无”，而是 Item 生命周期

OpenAI 对 Codex App Server 的公开说明把一次 Agent 工作拆成三个层次：

- Thread：持续的任务会话，承载多轮上下文。
- Turn：一次由用户输入触发的完整工作回合。
- Item：回合里的用户消息、Agent 正文、工具执行、审批请求、diff 等具体事件。

每个 Item 都有 started、delta、completed 生命周期。UI 因此可以先显示“正在编辑 / 正在检查 / 正在运行”，再用完成态替换，而不是在消息底部长期放一组静态按钮。

### 8.2 对 CVAgent 的新结论

上一版“用户也不使用气泡”的决策过度纠偏，应该改为：

| 内容 | 表达方式 | 说明 |
| --- | --- | --- |
| 用户输入 | 右侧浅灰轻气泡 | 保留对话方向感，但不使用蓝色高亮和头像 |
| Agent 回复 | 左侧正文流 | 不显示角色名和头像，不套大卡片 |
| 工具执行 | 可折叠过程行 | 例如“读取简历”“检查页面密度”“重新渲染” |
| 执行中 | 中性扫光 / 低对比动态点 | 只在 started 到 completed 期间出现 |
| 执行完成 | 灰色完成态 | 不用绿色、红色、蓝色状态徽章 |
| 阻断信息 | 正文中说明，顶部和排版检查页承载严重度 | 对话内不再重复红色警告 |
| 业务动作 | 只在确实存在产物、审批或外部变更时出现 | 不使用“采纳建议”“打开预览”这种泛化按钮 |

### 8.3 为什么删除当前两个按钮

“采纳建议”只是把 Agent 原话复制到输入框，用户仍然需要再次发送，属于重复交互；“打开预览”在 CVAgent 工作台中也重复，因为 A4 预览已经常驻右侧。两者都不构成独立产物或审批节点，应删除。

真正需要保留的业务入口是：

- 工作台顶部的 Agent 开关。
- 工作台右侧的 A4 预览和手动微调。
- 排版检查页的阻断项处理入口。
- 当未来接入真实渲染任务时，工具过程行的展开详情和错误重试。

### 8.4 多轮对话链路目标

```text
用户输入（浅灰气泡）
        ↓
Turn 开始：正在读取当前简历
        ↓
工具过程：检查内容 / 计算页数 / 渲染模板
        ↓
Turn 完成：Agent 给出结果与下一步说明
        ↓
用户继续输入，上一轮过程收起但可回看
```

Demo 必须至少演示 started → running → completed 三个状态；不能只把用户文字 append 到列表然后结束。真实接入时，前端应映射 Agent harness 的事件流，而不是靠 CSS 假装“AI 正在思考”。

### 8.5 视觉和动效验收补充

- 用户气泡只承担消息归属，不承载操作按钮。
- Agent 正文和工具过程之间用间距与极浅分割线建立层级。
- 工具行默认收起，点击行本身展开详情，不额外放“查看详情”按钮。
- 运行中只允许一处中性灰扫光或三个灰点，完成后停止。
- 输入框始终固定可见；发送后消息立即进入流，工具过程在其后出现。
- 多轮消息按 Turn 分组；时间和耗时只在组级别显示一次。
- 失败、需要用户决定或需要权限时，才出现明确的内联操作；普通建议不生成按钮。

本修正以 OpenAI 的公开 Codex App Server 说明为协议依据，并结合 OpenHands 等开放 Agent UI 对“会话、工具状态、最近对话”的分层做交互归纳；不声称复制任何厂商的私有 CSS 或源码。
